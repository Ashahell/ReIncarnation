# A0: drum-section tails — counters, host bench, Dell regression

Date: 2026-10-07. Build: host `-O2` (this machine); Dell runs PENDING
(owner RIAPP up on the Dell — no lane runs without the owner's word, §2).

## Decision rule (written before reading the results)

- **"Polyphony":** Dell fit `µs = a + b × active` gives `r` ≥ 0.95 for the
  909 and the 808, **and** no single voice costs more than 2× the median
  voice per voice-sample on the host bench. Then the tail is polyphony:
  stop Part A with the negative result (A2), no engine change.
- **"Outlier":** otherwise, name the outlier (voice, code path, or block
  type) and go to A1.

## What was built (commit: drum-tail A0)

- `vc_samples` / `vc_voice_active` on `RB909Set` / `RB808Set`, reset once
  per block by the engine before each section render (the levi `vc_*`
  discipline). 909: +1 per active voice per sample, +1 more for a live flam
  second playhead. 808: +1 per slot whose selected voice is active (an
  active-but-unselected switch partner does no work and counts 0).
  Counting never touches audio: the three song hashes are unchanged
  (demo `238113a7962c112f`, ZB `26eb9a9911173c20`,
  KN `13dc42d73d85998b`, `tools/songplay IN.rbng OUT.wav --hash`).
- Dell pairing with no extra clock reads: S808/S909 use `RI_ESTAGE_E_STORE`
  into `drum_last808_us` / `drum_last909_us` (same pair the stage already
  pays), and `ri_engine_drum_sample` keeps every 256th full 64-sample
  block into a 512-entry ring, then stops (512 × 256 × 64 ≈ 175 s at
  48 kHz). Partial (event-split) slices never tick the stride. No clock,
  no record. The app dumps the ring at close as `RIAPP drumdiag` lines,
  gated on `RIAPP_DIAG`.
- Laws in `tests/unit/t175_drum_counters.c` (gated in `ri_audit.sh`):
  silence reads 0; k voices read k × 64; flam steady state reads 128 with
  the fire block strictly between; 808 shared slot (RS+CL) reads 64 with
  both voices still active; engine counters describe the last block alone;
  ring stride/span/partial-skip/stop-full mechanics under a fake clock.
- Mutants, all killed (each: `ri_build_host.sh all`, then
  `test t175_drum_counters`): drop the flam +1 → fire/post blocks read 64;
  count 808 voices instead of slots → shared slot reads 128; E_STORE back
  to E on S909 → `us909` reads 0; ring cap removed → stack smashing abort.
- Bench `tests/unit/drum_bench.c` (ungated, `UNGATED_ALLOW` reason recorded
  in the audit): held k = 0…all, per-voice solos, flam on/off, median-of-7
  with min/max, every row with its counter CONTROL.

## Named host outlier (decision-rule input, NOT the verdict)

Crash/ride: `decay_env()` in `engine/dsp/rb909.c` runs `ri_pow2` (via
`rb909_decay_scale`) + `ri_exp` per sample per playhead, and only CR/RD
take that branch (`accent_noop`). Extra ≈ (9693.3 − 4648.3)/64 ≈
78.9 ns/voice-sample ≈ 5.0 µs/block on this host. The extra envelope is
by design (Tune-shortened crash/ride decay, per-voice ledger rows) and
audible — no bit-exact cheaper form exists (a control-rate or recursive
envelope changes samples). Whether it is worth anything on target, and
whether the Dell tail tracks it, is the Dell regression below. If the
regression says polyphony (r ≥ 0.95) the CR/RD price is still real but
the tail is not a defect: record both, stop.
