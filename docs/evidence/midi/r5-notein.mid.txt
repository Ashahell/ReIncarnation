# R5 note-in lane proof — an external sequencer plays the ReBirth voices.
#
# Sent into cluster `riapp` with MIDISEND while RIAPP runs, exactly as
# `m4-levi.mid.txt` is. NO USB-MIDI DEVICE IS NEEDED: MIDISEND plays a script
# into the CAMD cluster on the SAME MACHINE, so this is CAMD into CAMD, not a
# cable. An earlier note in the ledger claimed R5 was unhearable for want of
# a device; that was wrong and is corrected.
#
# WHAT IS BOUND, AND WHY THE SCRIPT LOOKS LIKE THIS
# (from `midi_settings_notein_ch`, which is the one function that decides):
#
#   channel 10  -> the 808. GM PERCUSSION, NOT A CHOICE (R6f). Implicit, so
#                 this script hits it with no switch and it is bound.
#   channel  2  -> 303A. The 303s follow `note_ch`, which with no explicit
#                 RIAPP_MIDI_NOTECH is the panel channel (default 2).
#   channel  3  -> NOTHING. Deliberately included below, and the law is that
#                 it is SILENT: an UNCLAIMED channel is skipped before the
#                 resolver is even called, so it is not a refusal.
#   the  909   -> NOT BOUND. `in909_ch` is unassigned and NEVER DEFAULTED
#                 (owner ruling 2026-10-12: the 808 answers GM channel 10 and
#                 the 909 stays off until its own channel is set). So notes
#                 on channel 5 are silent too, and that is CORRECT.
#
# THE COUNTERS ARE THE POINT. Read `NOTEIN played= refused=` from the ev-log
# BEFORE listening:
#   refused=0, played>0  -> the binding is right and the fault is downstream
#                           (an engine or a ring problem)
#   refused>0            -> messages ARE arriving and the map is wrong; no
#                           amount of listening produces a sound
#   played=0 refused=0   -> nothing is arriving at all: a cluster or a
#                           receiver problem, not a mapping problem
#
# Those three are different faults with the same symptom ("it is quiet"), and
# the counters separate them without a sound.
#
# CORRECTED 2026-10-13, STILL UNHEARD. Sections 2, 3, 6 and 7 sent 90/80
# and section 4 sent 9A while their comments claimed channels 2 and 10 --
# those bytes are channel 1 and channel 11, and NOTHING HAS BOUND EITHER.
# The Dell's own ev-log settles what was bound: `NOTEIN dev 0 ch 2 bound`,
# `dev 2 ch 10 bound`. So every note meant for the 303 would have been
# skipped as unclaimed and section 4 would never have moved `refused`,
# meaning the script as written could not have produced the readings its
# comments promise.
#
# The bytes now match the comments (91/81 for channel 2, 99 for channel 10)
# per `midi_levi.c:183`. THAT ARITHMETIC IS CHECKED AGAINST CODE, NOT
# AGAINST SOUND: this script still has no captured run output, and its
# verdict lines above describe readings that have not been observed. Do not
# cite `played=` or `refused=` from this file as a result until an ear proof
# runs it and the counters are read.

# --- 1. THE 808 ON GM CHANNEL 10. Must sound. ---------------------------
99 24 64   B0 kick
D 120
99 24 00
D 90
99 26 64   rim/snare
D 120
99 26 00
D 90
99 2A 64   closed hat
D 60
99 2A 00
D 90
99 24 7F   kick, loud
D 240
99 24 00
D 300

# --- 2. THE 303A ON CHANNEL 2. Must sound. ------------------------------
# 91 = note-on, low nibble 1 -> channel 2. 90 would be channel 1, which
# nothing has bound, so it would land in `unclaimed` and stay silent while
# looking like a pass to anyone reading only `refused`.
91 24 64   C1, low
D 240
81 24 00
D 60
91 2C 64   C2
D 240
81 2C 00
D 60
91 2E 7F   D2, loud
D 360
81 2E 00
D 400

# --- 3. A HELD CHORD ON THE 303, so a stuck note would be audible -------
91 30 64
91 34 64
91 37 64
D 480
81 30 00
81 34 00
81 37 00
D 400

# --- 4. THE UNMAPPED GM NOTE. MUST BE REFUSED, AND COUNTED. -------------
# This is the only line here that should make `refused` move. It is on a
# CLAIMED channel (10) with a note number the deliberately partial GM table
# does not carry, so the channel is bound but the note resolves to nothing.
#
# CHANNEL ARITHMETIC, because this line previously had it backwards. The
# status byte carries the channel in its LOW NIBBLE, 0-BASED, and MIDI
# names it 1-based -- which is exactly what `midi_levi.c:183` does:
# `ch = (status & 0x0F) + 1u`. So nibble 9 -> channel 10 -> byte 0x99.
# 0x9A is nibble 10 -> CHANNEL 11, which is bound to nothing here, so it
# would be skipped as unclaimed and `refused` would never move -- the exact
# assertion this section exists to make.
99 78 64   GM note 120 on channel 10: not in the partial map -> refused
D 300

# --- 5. THE UNCLAIMED CHANNELS. MUST BE SILENT, AND MUST NOT BE COUNTED -
# Channel 3 and channel 5 are both unbound. The law is that an unclaimed
# channel is skipped BEFORE the resolver, so these move NEITHER counter. A
# note that moves `refused` here would mean the channel table is claiming
# channels it does not own, which is a different bug from a wrong note.
93 24 64   channel 4: unbound -> silent, not counted
D 180
83 24 00
D 120
95 24 64   channel 6: the 909 is unbound -> silent, not counted
D 180
85 24 00
D 120
92 24 64   channel 3: unbound -> silent, not counted
D 180
82 24 00
D 400

# --- 6. VELOCITY 0 IS A NOTE-OFF, not a note-on at zero velocity ---------
# A live 303 note that never stops is a hung voice, and this is the idiom
# every DAW uses to save bytes. If `on` were read from the status alone,
# every one of these would ring until its envelope finished.
91 26 64   E1 on
D 240
91 26 00   E1 "off" as note-on velocity 0
D 120
91 26 7F   E1 on again
D 240
81 26 00   E1 off by status
D 400

# --- 7. A DRUM NOTE ON A MELODIC CHANNEL MUST NOT SOUND A DRUM ----------
# Channel 2 is the 303. GM kick (36) there is an ordinary low note on a 303,
# NOT a kick drum. If a drum sounds here, the 808's channel is not exclusive.
91 24 7F   GM 36 on the melodic channel: a low 303 note, not a kick
D 300
81 24 00
D 500
