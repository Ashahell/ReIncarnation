## Corpus (tests/unit/t172_levi_bitexact.c, 19 cases x 2 block sizes)

Each case renders >= 2 s at 48000 Hz through `levi_voice_render_sum_stereo`,
once in 64-sample blocks and once in 256-sample blocks. Hash = FNV-1a 64 over
the `uint32_t` bit pattern (via `memcpy`) of every L and R sample.

## Mutation proofs (each: mutate, rebuild dsplevi, FAIL; revert, rebuild, PASS)

Object-discipline note: `ri_build_host.sh test` links the objects in
`/tmp/ri/build` without rebuilding them, so every mutant cycle rebuilt
`dsplevi` first and `md5sum levi.o` was checked. One reverted-without-rebuild
cycle baked a mutant pin (f8af) and was caught by re-generating pins from a
fresh rebuild; the stale pin was replaced by 7daa. Lesson recorded.

M2a prescribed clamp `tpt_g` 1.45f -> 1.44f: SURVIVED (see below).
M2b live filter-coefficient mutant, `3.14159265f` -> `3.14160000f` (tpt_g w):
```
FAIL tests/unit/t172_levi_bitexact.c:528: case algos blk64: got 94f2b5acbbb84a87 want bfefc6b334453d07
... (all filter-audible cases fail)
```

Why M2a survives: `levi_voice_render_stereo` hard-clamps `dc`/`ac` to
[20, 20000] Hz before `voice_chain`, so `w = pi*fc/sr <= 1.31 < 1.44` and the
`tpt_g` clamp never fires through any reachable render path (`tpt_g` is
`static`, so no direct unit call exists). The afilt corpus was extended with
max-cutoff x max-keytrack at note 127 to reach for the clamp; the mutant still
passes, confirming unreachability rather than corpus weakness. M2b proves the
oracle sees coefficient changes.
