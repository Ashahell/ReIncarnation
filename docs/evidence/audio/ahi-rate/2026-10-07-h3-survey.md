## Fixes (one hunk each, branch `ahi-report-selected-rate`)

- HDAudio, NVHDMI: write back `frequencies[selected_freq_index]` after the
  choice (HDAudio placed after the CANRECORD loop so record gating still
  sees the exact request).
- SB128, CMI8738, Envy24, Envy24HT: in `AllocAudio`, when the request
  matches no listed rate (`i == FREQUENCIES` out of the existing CANRECORD
  loop), write back the same fallback `Start` will program
  (44100/44100/48000/48000). Exact requests are untouched by construction.
- Compile-only except HDAudio: all six relink clean for ABIv1
  (`hdaudio/nvhdmi/sb128/cmi8738/envy24/envy24ht.audio`, §H2 evidence).
  No hardware on hand for NVHDMI/SB128/CMI8738/Envy24/Envy24HT — stated
  as compile-only in the PR draft. No driver was behavior-tested beyond
  HDAudio-on-Dell (pending owner "yes").
