# F2: speed — UC confirmed, and it explains 220 MB/s

Date: 2026-10-07. Same Dell session as F1 (agent e6320, session 1).
Probe: `lane/blitprobe/` (`blitprobe.c` verbatim from the B0 addendum plus
the manual dos open; `build.sh`), `RAM:BLITPROBE >RAM:BLITPROBE.LOG`.

## Baseline, verbatim

```
depth=24 bytes/frame=2097152 (at 4 B/px)
RAM->RAM  BltBitMap        480 us/frame  4369 MB/s
RAM->WIN  BltBitMapRastPort 9509 us/frame  220 MB/s
WIN       RectFill full    9274 us/frame  226 MB/s
WIN       RectFill 1-row x1000  18568 us total  18 us/row
```

Matches the B0 addendum (484 / 9530 / 9290 µs) within run noise.

## Conclusion (GF2)

F1 says the framebuffer is **UC**, so per the phase rule the statement is
plain: **220 MB/s is what uncached writes over this path deliver, and
4369 MB/s RAM→RAM shows the CPU is not the limit.** Every pixel that reaches
the screen crosses the slow path exactly as measured — `fl` (4–15 ms per tab
switch) and the MUI backfill/rack-art share of `mui`. No further measurement
is needed to explain the speed; F3 (WC trial) is the owner's decision.
