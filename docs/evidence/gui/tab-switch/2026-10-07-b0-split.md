## Stop rule (written before reading any table)

If `fb + fr` (the part a replay skip can remove) is **below 50 % of
`page_us`** on every tab, **or below 8 ms** on every tab, the cost is MUI's
and the blit's: stop Part B with the negative result (B3). Otherwise go to
B1. (`mui`'s composition gets written down as far as it can be told, but
prebuilt Zune code is not optimised — 2026-10-03.)

## What was built (commit: tab switch B0)

- `gui/widgets/rsection.mcc.c` `draw_frame` full path: the same two calls
  `draw_section` makes (`build_dl` whole-section + `replay_dl`), timed as
  three abutting spans sharing EClock samples (the 2026-10-05 partial-path
  pattern). One read ends the build and starts the replay; the next ends
  the replay and starts the blit. Pixel-identical by construction (same
  calls, same args, same target). Untouched when `RIAPP_DIAG` is off: same
  calls, no reads. Costs one extra `ReadEClock` (~2.2 µs) per full draw
  when on (four reads where three were).
- `RSectionDiag` carries `df_build_max/sum`, `df_replay_max/sum`,
  `df_blit_sum` (the full-draw blit max stays `blit_max`). `df_sum/df_n`
  keep their wall-total meaning (they also cover the prologue µs before
  the build starts). All zero with the switch off.
- `app/riapp.c` `tab_switch`: per-switch deltas of the `df_*` sums over
  all canvases (integer adds, no clock reads of its own) give `fn` (full
  draws), `fb`, `fr`, `fl`; `mui = page_us − (fb + fr + fl)` (signed) is
  MUI's own page handling, layout, backfill and anything outside our draw.
  `mui` must never read negative — the draws run inline inside the
  `SetAttrs`, so the spans are disjoint by construction and a negative
  `mui` means the instrument overlaps. With the switch off the df sums
  stay zero: `fn/fb/fr/fl` read 0 and `mui == page_us` ("not measured").
- TAB line keeps every old field and appends
  `fn/fb/fr/fl/mui` (`evlog` buffer 192 → 256: the longer line truncated).
- Host law `tests/unit/t176_tab_split.c` (gated): the four parts partition
  `page_us` exactly; `mui` never negative; zero draws → zero sums; shared
  samples abut with no residue; the contrast (a `mui` that forgets the
  blit) over-attributes by exactly `fl` — the named failure mode, in-test,
  the same shape as t168's `gap_max` contrast (the widget is AROS-only, so
  the production mutant cannot execute on the host).
- `RIAPP drumdiag` ring dump rides the same `RIAPP_DIAG` gate at close
  (A0's Dell instrument).

## Verdict: STOP (negative result, stop rule applied as written)

`fb + fr` is below 50 % of `page_us` on every tab (max 19.9 %) AND below
8 ms on every tab (max 4.8 ms). Both stop conditions hold: the cost is
MUI's and the blit's. No B1, no B2.

What remains and who owns it: `mui` (MUI's own page handling, layout of
the newly shown canvases, backfill — 3–28 ms depending on page
complexity) and `fl` (the window blit, 4–15 ms). Neither is removable by
a replay skip; prebuilt Zune code is not optimised (2026-10-03). A replay
skip would remove at most `fb + fr` (≤ 4.8 ms) while adding stale-pixel
risk — not worth it. The switch stays 20–42 ms: one to two 60 Hz frames,
no audio impact (xruns+0 throughout).

## Addendum (advisor review, 2026-10-07): the remaining cost is screen write bandwidth

The verdict above stands for the question it asked: a replay skip would save
at most 4.8 ms. Its attribution, "MUI's and the blit's", is incomplete,
because the blit `fl` alone is 4–15 ms per switch. A RAM-to-RAM copy of a
whole canvas should take well under 1 ms. A direct throughput probe (source
below) on the Dell (ABIv11, VESA 1366x768, depth 24), while RIAPP was
running, two runs:

```
depth=24 bytes/frame=2097152 (at 4 B/px)
RAM->RAM  BltBitMap        484 us/frame  4332 MB/s
RAM->WIN  BltBitMapRastPort 9530 us/frame  220 MB/s
WIN       RectFill full    9290 us/frame  225 MB/s
WIN       RectFill 1-row x1000  18882 us total  18 us/row
(second run: 483 / 9521 / 9284 us, 18866 us total)
```

- **Writes to the screen run at about 220 MB/s, about 20x slower than
  memory-to-memory (4332 MB/s).**
  - Even a solid `RectFill` of a 1024x512 window area costs 9.3 ms.
  - So the cost is not the fill and not the blit as such; it is getting
    the pixels onto the display.
- **The mechanism**, read in the AROS source
  (`rom/hidds/vesagfx/vesagfx_support.c`): the VESA driver draws into a
  shadow bitmap in RAM, then `UpdateRect` copies each changed rectangle to
  the linear framebuffer with `CopyMem`. The framebuffer is mapped through
  `HIDD_PCIDriver_MapPCI`, and nothing in `rom/hidds/vesagfx` sets
  write-combining (no MTRR/PAT use in the driver).
  - About 220 MB/s is the typical rate for **uncached** writes to a PCI
    framebuffer; a write-combined mapping is normally several times faster.
  - That the framebuffer is uncached is the **likely** cause, inferred from
    the rate and the source. The MTRR/PAT state on this Dell has not yet
    been read, so it is not proven.
- **What it explains:**
  - `fl` (4–15 ms per switch): a canvas of roughly 1.6–3.3 MB at 220 MB/s
    takes 7–15 ms;
  - a large part of `mui`: MUI's backfill and the rack art drawn straight
    into the window go through the same `UpdateRect` path;
  - why the plate cache and the rail page group helped. They removed
    work, but every pixel that changes still crosses the same slow path.
- **The real levers for tab switch and every other repaint on the Dell:**
  1. **AROS side:** map the VESA framebuffer write-combining (PAT or MTRR)
     in the vesagfx driver or the kernel's PCI mapping. This benefits every
     AROS app on VESA hardware, so it is upstream work and therefore the
     owner's call (outward-facing).
  2. **App side, smaller:** do not write pixels twice. On a page switch MUI
     backfills the page area and our canvases then blit over it, so every
     canvas pixel crosses the slow path twice. Suppressing the backfill
     under canvases would roughly halve those bytes. This is not measured
     yet.

### Probe source (ABIv11; build with the `ri_build_v11.sh` flags, link `startup.o -lamiga -lintuition -lgraphics -ldos -lexec -lautoinit`)

```c
#include <exec/types.h>
#include <devices/timer.h>
#include <intuition/intuition.h>
#include <graphics/gfx.h>
#include <proto/exec.h>
#include <proto/dos.h>
#include <proto/intuition.h>
#include <proto/graphics.h>
#include <proto/timer.h>
struct Device *TimerBase;
static ULONG ef;
static UQUAD now(void) { struct EClockVal e; ReadEClock(&e); return ((UQUAD)e.ev_hi << 32) | e.ev_lo; }
static ULONG us(UQUAD a, UQUAD b) { return (ULONG)((b - a) * 1000000ULL / ef); }
int main(void) {
    struct timerequest tr;
    struct Window *w;
    struct BitMap *bm, *bm2;
    struct RastPort brp;
    int W = 1024, H = 512, i, N = 20, d;
    UQUAD t0, t1;
    ULONG u, mb;
    if (OpenDevice((STRPTR)"timer.device", UNIT_ECLOCK, (struct IORequest *)&tr, 0)) return 20;
    TimerBase = tr.tr_node.io_Device;
    { struct EClockVal e; ef = ReadEClock(&e); }
    w = OpenWindowTags(NULL, WA_Left, 40, WA_Top, 40, WA_InnerWidth, W, WA_InnerHeight, H,
        WA_Title, (IPTR)"BLITPROBE", WA_Flags, WFLG_DRAGBAR | WFLG_DEPTHGADGET | WFLG_ACTIVATE, TAG_DONE);
    if (!w) { Printf("no window\n"); return 20; }
    d = GetBitMapAttr(w->RPort->BitMap, BMA_DEPTH);
    bm = AllocBitMap(W, H, d, BMF_MINPLANES, w->RPort->BitMap);
    bm2 = AllocBitMap(W, H, d, BMF_MINPLANES, w->RPort->BitMap);
    if (!bm || !bm2) { Printf("no bitmap\n"); CloseWindow(w); return 20; }
    InitRastPort(&brp); brp.BitMap = bm;
    SetAPen(&brp, 3); RectFill(&brp, 0, 0, W - 1, H - 1);
    mb = (ULONG)W * H * 4u;
    Printf("depth=%ld bytes/frame=%lu (at 4 B/px)\n", (LONG)d, mb);
    t0 = now(); for (i = 0; i < N; i++) BltBitMap(bm, 0, 0, bm2, 0, 0, W, H, 0xC0, 0xFF, NULL); t1 = now();
    u = us(t0, t1) / N; Printf("RAM->RAM  BltBitMap        %lu us/frame  %lu MB/s\n", u, u ? mb / u : 0);
    t0 = now(); for (i = 0; i < N; i++) BltBitMapRastPort(bm, 0, 0, w->RPort, w->BorderLeft, w->BorderTop, W, H, 0xC0); t1 = now();
    u = us(t0, t1) / N; Printf("RAM->WIN  BltBitMapRastPort %lu us/frame  %lu MB/s\n", u, u ? mb / u : 0);
    SetAPen(w->RPort, 2);
    t0 = now(); for (i = 0; i < N; i++) RectFill(w->RPort, w->BorderLeft, w->BorderTop, w->BorderLeft + W - 1, w->BorderTop + H - 1); t1 = now();
    u = us(t0, t1) / N; Printf("WIN       RectFill full    %lu us/frame  %lu MB/s\n", u, u ? mb / u : 0);
    t0 = now(); for (i = 0; i < N * 50; i++) RectFill(w->RPort, w->BorderLeft, w->BorderTop + (i % H), w->BorderLeft + W - 1, w->BorderTop + (i % H)); t1 = now();
    u = us(t0, t1); Printf("WIN       RectFill 1-row x%ld  %lu us total  %lu us/row\n", (LONG)(N * 50), u, u / (N * 50));
    FreeBitMap(bm); FreeBitMap(bm2); CloseWindow(w); CloseDevice((struct IORequest *)&tr);
    return 0;
}
```
