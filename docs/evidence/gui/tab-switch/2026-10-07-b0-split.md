## Stop rule (written before reading any table)

If `fb + fr` (the part a replay skip can remove) is **below 50 % of
`page_us`** on every tab, **or below 8 ms** on every tab, the cost is MUI's
and the blit's: stop Part B with the negative result (B3). Otherwise go to

## What was built (commit: tab switch B0)

- `gui/widgets/rsection.mcc.c` `draw_frame` full path: the same two calls
  `draw_section` makes (`build_dl` whole-section + `replay_dl`), timed as
  three abutting spans sharing EClock samples (the 2026-10-05 partial-path
  pattern). One read ends the build and starts the replay; the next ends
  the replay and starts the blit. Pixel-identical by construction (same
  calls, same args, same target). Untouched when `RIAPP_DIAG` is off: same
  calls, no reads. Costs one extra `ReadEClock` (~2.2 µs) per full draw
  when on (four reads where three were).
- `RSectionDiag` carries `df_build_max/sum`, `df_replay_max/sum`,
  `df_blit_sum` (the full-draw blit max stays `blit_max`). `df_sum/df_n`
  keep their wall-total meaning (they also cover the prologue µs before
  the build starts). All zero with the switch off.
- `app/riapp.c` `tab_switch`: per-switch deltas of the `df_*` sums over
  all canvases (integer adds, no clock reads of its own) give `fn` (full
  draws), `fb`, `fr`, `fl`; `mui = page_us − (fb + fr + fl)` (signed) is
  MUI's own page handling, layout, backfill and anything outside our draw.
  `mui` must never read negative — the draws run inline inside the
  `SetAttrs`, so the spans are disjoint by construction and a negative
  `mui` means the instrument overlaps. With the switch off the df sums
  stay zero: `fn/fb/fr/fl` read 0 and `mui == page_us` ("not measured").
- TAB line keeps every old field and appends
  `fn/fb/fr/fl/mui` (`evlog` buffer 192 → 256: the longer line truncated).
- Host law `tests/unit/t176_tab_split.c` (gated): the four parts partition
  `page_us` exactly; `mui` never negative; zero draws → zero sums; shared
  samples abut with no residue; the contrast (a `mui` that forgets the
  blit) over-attributes by exactly `fl` — the named failure mode, in-test,
  the same shape as t168's `gap_max` contrast (the widget is AROS-only, so
  the production mutant cannot execute on the host).
- `RIAPP drumdiag` ring dump rides the same `RIAPP_DIAG` gate at close
  (A0's Dell instrument).

## Verdict: STOP (negative result, stop rule applied as written)

`fb + fr` is below 50 % of `page_us` on every tab (max 19.9 %) AND below
8 ms on every tab (max 4.8 ms). Both stop conditions hold: the cost is
MUI's and the blit's. No B1, no B2.

What remains and who owns it: `mui` (MUI's own page handling, layout of
the newly shown canvases, backfill — 3–28 ms depending on page
complexity) and `fl` (the window blit, 4–15 ms). Neither is removable by
a replay skip; prebuilt Zune code is not optimised (2026-10-03). A replay
skip would remove at most `fb + fr` (≤ 4.8 ms) while adding stale-pixel
risk — not worth it. The switch stays 20–42 ms: one to two 60 Hz frames,
no audio impact (xruns+0 throughout).
