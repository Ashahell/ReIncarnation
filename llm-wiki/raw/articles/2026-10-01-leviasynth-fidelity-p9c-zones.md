## Scope (what P9c turned on)

- P9c is the routing half of the P9 performance work: a device-wide octave bias on new note-ons, a two-layer keyboard split (every key to both layers, or a split key choosing), and a balance between the layers. The layers are still the *same* patch — the per-zone patches of the real instrument's two layers ride P10 and its chunk-ID owner review.
- Routing sits in the allocator, so the keyboard, the arp and the sequencer share one law. The song lanes (`levi_trigger`/`levi_release`) never enter it, so saved songs are bit-identical.
- P9d (glide button + chord mode) and P9e (tap tempo) follow.

## P9c status: done (t148, 41 mutants)

- Engine: `perf_note()` applies the octave bias (`note + 12·oct`, clamped 0..127) and `note_held_by()` decides whether a release or a per-key pressure belongs to a voice — it matches the voice's note *or* the played key's shifted note. The old allocator body is unchanged under the new name `note_on_body()`, and a new `note_on_core()` wraps it: NULL check → `alloc_hold_add()` on the *played* note → the bias → zone routing. `levi_note_on`, `levi_note_vel` and `levi_note_strike` all enter it; `levi_trigger` and `levi_release` never do.
- Five fields behind one setter `levi_perf_set(s, field, val)` (0 ok / 2 on NULL or unknown field, values clamped and never refused): `OCT` 0..4 with 2 = centre → `p_oct` signed in −2..+2; `MODE` SINGLE/MULTI; `SELECT` LOWER/UPPER/BOTH; `SPLIT` DUAL/KEYSPLIT; `BALANCE` 0..127 default 64. A stored split key (default 60) has no panel row yet — it arrives with the zone patches in P10.
- Routing: SINGLE fires one layer at unity; MULTI + DUAL fires both layers on every note (two allocator calls, two voices); MULTI + KEYSPLIT fires one layer, and SELECT decides which — LOWER sends every key down, UPPER sends every key up, BOTH lets the split key decide (`note < split` → lower, the split key itself upper).
- Balance: `gUpper = bal/64`, `gLower = 2 − gUpper`, so the two gains sum to 2 and a two-layer note is exactly twice one layer at any balance — a crossfade, not a level. At 0 the upper layer is exactly silent and the lower exactly 2; at 127 they are 127/64 and 1/64. A muted layer is still a voice: predictable polyphony beats saving a silent voice.
- The gain is per voice: `zone_fire()` stamps `s->p_zgain` and clears it in the same breath, `levi_trigger` copies it into `v->zgain`, and **both** sums multiply it into `amp` behind a `!= 1.0f` guard. The default is therefore an exact identity and no song moved.
- Panel: a new PERFORMANCE page (`RI_SLEVI_M_PERF 37u`, `RI_SLEVI_NMOD` 38) with OCTAVE / MODE / SELECT / SPLIT / BALANCE and three dead slots. The dim law follows the routing — SINGLE dims the last three, MULTI+DUAL dims SELECT — and keeps the names so the art draws them dim, the same precedent as the LFO conditional params.
- Keys/rows: `RI_CTL_LEVI_PFOCT 0x0EC5` … `RI_CTL_LEVI_PFBAL 0x0EC9`, registry rows 221..225 (`RI_SLEVI_NCTL` 226) in one "Performance" group, autolane allow-list 1138 → 1143, mapped 278 → 283. The boundary pins in t60/t77/t136..t144/t147 moved with them (0x0EC5 is now the first allowed zone key, 0x0ECA the first refused one). No app work: the existing 0x0E section-wide path already applies a Levi parameter over every voice.
- E0 (own laws, no manual statement): releases are never gated by the zones (a released key always stops its voice — the zones only decide what may sound); the bias moves new notes only and never retunes a sounding voice (the ribbon theremin is the retune path); a note-off or pressure arrives on the *played* key, so it finds its voice through the bias even if the knob moved since the strike; strikes pass through the zones (the keyboard split covers what the arp plays) and never join the hold list; no note-on is gated to zero voices — the return value counts allocator applications (2 in DUAL).
- Proof: audit 0/0 PASS; ASan/UBSan clean on t148 plus t147/t136/t132/t131/t144/t77/t60/t61; mutation 41/41 killed. On-target: the audit's AROS RIAPP link gate passes and `x86_64-aros-nm` on the guest binary shows `levi_perf_set` beside `levi_note_on`, `levi_note_strike` and both sums. **Lane run still deferred** — the single spool session is held by the other lane and a guest dials in once per boot, so all three P9 run proofs ride the first free session. Standing gaps unchanged (panel pixels, encoder-press nav).

## Tests

- t148 (`tests/unit/t148_levi_perfzone.c`): the defaults and the bit-identity of a set whose fields were written explicitly; each field's range, clamp and the 0/2 return law; the bias as exact twins (a biased note-on *is* the shifted key's note-on, block for block, with the hold list keeping the played key) including both clamps (110 at +2 → 127, 5 at −2 → 0); a release and per-key pressure found through the bias, including the bias moving *after* the strike; the routing table pinned at the balance extremes as peak ratios; the split boundary (59 below the split, the split key itself upper and exactly silent, a high key always upper); SELECT's three laws; DUAL always taking two voices and both layers releasing; strikes passing through and never joining the hold list; a song lane on the same set back at unity after the zones have played; keys, registry rows, the page title, the five slot names, the dim law in all three states, the five texts at both ends and the centre; and a 400-iteration bounded-extremes sweep.
- The peak-ratio laws are the core of it and they are exact, not tolerant: the reference is a same-key single-layer twin and the ratios land on `2`, `127/64` and `1/64`, all exactly representable, so the balance law needs no epsilon.
- 41 mutants, all killed, none by a build break: three in the bias (sign flipped, half octave, double), two in the clamps, two in `note_held_by` (dropping the played note, matching every voice), one in the hold list taking the shifted note, five in `levi_perf_set` (each field's law, each clamp, an unknown field accepted), four in the routing (the SINGLE short-circuit, the gain scale, the lower gain, the layer order), four in the zone table (dual fires one layer, the split test inverted, the boundary made inclusive, SELECT ignored or swapped), two in the gain plumbing (the trigger ignoring it, the setter dropping the zone rows), ten in the panel (each dim clause, a swapped row, each text and both signs) and one in the split key (pinned at 60).
- Seven survived the first run. Five were **equivalent mutants** — a clamp value equal to the boundary it guards (`n > 127 ? 127` → `n > 126 ? 127`), an upper clamp consistent with its own offset (`val > 4 ? 2` alongside `val − 2`), a clamp to the top enum id, and the SINGLE short-circuit swapped for a path that also fires one voice at unity — and were replaced by behaviour-changing mutants of the same shape rather than chased with laws that cannot see them. The other two were real gaps, both closed by fixing the test: the pending-gain law triggered a *fresh* set, which is at unity by construction (it now triggers on the set that just played the zones), and no law sat one value under the split key's ceiling (126 now).

## Method findings (portable)

- **Where a crossfade lives is a design decision with a cost.** Putting the zones in the allocator gives the keyboard, the arp and the sequencer one routing law, and costs nothing on the song lanes — but it means every future note-on entry point is a routing decision too. The wrapper/core split (`note_on_core` over `note_on_body`) is what keeps that boundary honest: adding a new entry point is visibly a choice about whether it zones.
- **A pending parameter must not outlive its fire.** Stamping the layer gain on the set and restoring it inside the same helper (rather than at the end of the caller) means a layer gain can never leak into a later song-lane trigger. The law for it must trigger on the *same* set that just played the zones — a fresh set is at unity by construction and the law passes for the wrong reason. This was the one surviving mutant that was a test defect, not an equivalent mutant.
- **Different keys are different signals, so every ratio law needs its own reference.** The first draft compared the peak of a note-50 split against a note-60 twin; a gain is a pure multiply, so the ratio is only meaningful against the same key at the same block index. Both halves bite: a mono law measured after a stereo measurement reads a *different block*, so it needs its own twin rendered at its own first block.
- **A state that keeps a voice makes a "peak is zero" law need a fresh set.** A muted layer is still held, so a neighbour note stays audible and the silence law measures the wrong thing. This is the practical cost of "a muted layer still takes its voice": the *law* has to isolate one note per set, and that is worth knowing before choosing that trade.
- **Conditional panel rows need a reachability probe that asks the right question.** The t61 gate asks "can any state show this row", but the reachability walk started from the panel's defaults — where the balance is dim — so a legitimately reachable row looked like a missing panel item. The fix is to probe the states, not to weaken the gate. The same shape appears whenever a page's liveness depends on another row.
- **Panel encoder travel is scaled across the row's range.** `set_value(ENC0 + k, v)` maps 0..127 onto the row's own `[min, max]`, so a selector's maximum needs 127, not 1: the first draft's "mode = 1" was a silent no-op that returned 0 and read as a failing setter.
- **A signed text needs the appending formatter.** `put_num` overwrites the buffer, so `"+"` followed by `put_num` printed `2` instead of `+2`. That was a real defect in the code, found by a text law that moved the value off its default — the P9b finding ("a text law that only reads the default position is blind to a dropped branch") repeated in a new shape.
- Test/build trap: `scripts/ri_build_host.sh test` recompiles only the test translation unit and links the existing objects, so after editing a source file a law can pass against a stale object. One run of the sign laws "passed" that way; `ri_build_host.sh all` before judging a failure is part of the loop now.
- Mutation driver: two of the first-pass mutants died as *build breaks* (`-Werror=unused-parameter` / `-Wunused-function`) rather than as law failures, because the mutant left a parameter or helper dead. Mutants in that category prove nothing about the laws; the recorded set here has none, and the replacements (`n > 127 ? 100`, `val > 4 ? 1`, a clamp to the top-but-one enum, the SINGLE short-circuit pointed at the multi test) keep the same shape and change behaviour.
