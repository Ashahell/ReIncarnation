## Scope (what P9d turned on)

- P9d is the last two slices of the P9 performance work: a **momentary glide button** (hold it and the next notes slide, release it and the voices go back to their own glide mode) and **chord mode** (a pushed lane chord fires from any one key, transposed by the key you play).
- Both are keyboard features layered on the routing that P9c installed: each chord lane enters `note_on_core()`, so a chord also passes the octave bias and the zone split (a dual-zone chord is 4 voices), and a song lane voice is not part of the player's chord.
- P9e (tap tempo, app level) follows; the per-zone patches of P10 and its chunk-ID owner review remain open.

## P9d status: done (t149, 51 + 8 mutants)

- Engine: `levi_glide_hold(s, on)` (0 ok / 2 on NULL) sets the device-wide `p_glidehold`. The *render* has no set pointer, so `levi_sig_refresh()` copies it into every voice's new `gforce` each block — the P9a home, already called by both sums — and the pitch law reads `gm = v->vglide ? v->vglide : (v->gforce ? 1u : 0u)`. The button therefore forces **glide mode 1**, never glissando, and P6b's glide time and curve are untouched: the button is the mode and nothing else.
- The three places a pitch moves between blocks read `s->p_glidehold` **directly**: `levi_trigger` (a fresh trigger), `alloc_fire` → `alloc_retune` (the legato path) and the ribbon's theremin retune (which is the same retune). So a press slides the very next note with no render in between, which a fire-time stamp could not do.
- Precedence is `mode → button → macro`: the DM_VOICE glide-toggle offset keeps the last word, so a macro can switch glide off while the button is held — the same shape as every other macro offset in P6b.
- Releasing the button **stops** a slide in progress: with `gm == 0` the whole glide block is skipped and the voice sounds its own note from that block on, leaving `glt` frozen where it stood. The plan's first draft said the slide "finishes, `glt` runs to 1"; the twin law settled it the other way and the plan line is corrected.
- Chord state sits on the set: `p_chord`, `p_chord_on` (lane bitmask), `p_chord_n`, `p_chord_note[RI_LEVI_NCHORD]`, with `RI_LEVI_NCHORD` = 6. `levi_chord_mode(s, on)` (0 ok / 2 on NULL) and `levi_chord_set(s, on_flags, notes, n)` (0 ok / 2 on NULL, NULL notes or `n` out of range; the stored mask is limited to `n`, so a shorter push really is shorter, and lanes past `n` are cleared). There is no other lane storage in the device — the app owns the chord buttons, as it owns the patch list.
- Fan-out lives only in `levi_note_on` and `levi_note_vel`; `levi_note_strike` never enters, so arp and sequencer lanes play their own notes. Each lane then enters `note_on_core()`, so a chord passes the P9c bias and zone routing; the return value is the total count across lanes.
- Transposition: the root is the lowest **on** lane (not lane 0 — the mask is what the player holds) and each lane lands at `lane + played − root`, clamped to 0..127, so the keyboard still transposes the chord. An empty chord is silent by design, with no fallback to the single note.
- Release and pressure: in chord mode any key release releases every voice in the hold list with the pending release velocity and empties the list, bypassing the poly-mode single-voice special cases (one voice cannot own a chord); `levi_note_rel_vel()` goes through the same path. Per-key aftertouch does the same, because the played key is in no voice — "pressure the chord" is the only thing a held chord can mean. A **song lane voice is in neither**: it is not in the hold list, so it is not the player's hold, and it sounds on past both.
- Songs bit-identical: both flags default 0, and the song path (`levi_trigger`/`levi_release`) never reads them.
- Panel: the PERFORMANCE page's dead slots 5 and 6 are GLIDE and CHORD (0/1, default 0). Both are live in every routing mode — they are not zone knobs, so the dim law does not reach them. Their texts come from the generic `RI_CK_SWITCH` branch, so the registry rows are SWITCH (the ribbon-touch precedent: an engine-bound on/off button), not SELECTOR.
- Keys/rows: `RI_CTL_LEVI_GLIDE 0x0ECA`, `RI_CTL_LEVI_CHORD 0x0ECB`, rows 226..227 (`RI_SLEVI_NCTL` 228), group "Performance", `RI_BIND_LEVI`, automatable; autolane allow-list 1143 → 1145, mapped 283 → 285, and `0x0ECC` is now the first refused key. The boundary pins in t60/t77/t136..t144/t147/t148 moved with them. Both rows reach the device from the same 0x0E section-wide case in `levi_set_param_ui` (the 8-voice loop is idempotent, as for every section-wide Levi parameter), so there is no app work.
- E0 (own laws, no manual statement): chord mode is off by default; an empty chord row makes a played key silent; strikes never enter chord mode; the root is the lowest `on` lane and the transposition follows the played key; per-key pressure in chord mode means the chord; the poly single-voice cases are bypassed for a chord release.
- Proof: audit 0/0 PASS; ASan/UBSan clean on t149 plus ten neighbours (t148/t147/t146/t145/t144/t136/t135/t134/t132/t131); mutation 51 mutants in `mut_p9d.txt` (47 killed, 5 of those by a build break) plus 8 replacements in `mut_p9d_r2.txt`/`mut_p9d_r3.txt`, every one killed behaviourally. On-target: the audit's AROS RIAPP link gate passes and `x86_64-aros-nm` on the guest binary shows `levi_glide_hold`, `levi_chord_mode` and `levi_chord_set` beside `levi_perf_set`, `levi_polyat` and `levi_note_off`. **Lane run still deferred** — the single spool session is held by the other lane and a guest dials in once per boot. Standing gaps unchanged (panel pixels, encoder-press nav).

## Tests

- t149 (`tests/unit/t149_levi_perfglide.c`): the button as an **exact twin** of the panel mode (mode-on versus mode-off-plus-button, eight blocks bit-identical), the mode winning over it (a glissando stays a glissando) and the macro winning over both, the stored glide time applying unchanged at 0; the per-block liveness (the refresh carries and drops `gforce`, a press slides the very next note with no render in between, a release hands the voice back, a press after the note does not retroactively slide it, a fresh voice starts on pitch); all three slide starts, including the legato/retune and ribbon-theremin paths; chord mode off by default and an explicit "off" bit-identical to never pushing the row; the push contract (six lanes fit, seven and a negative count refused, the mask limited to `n`, lane notes clamped, lanes past `n` cleared); four transposition cases; the root as the lowest `on` lane; both clamps, including the low one only a lane below the root can reach; an empty chord silent with no fallback; a strike playing its own note; the bias and the zone routing carrying a chord (a dual chord is 4 voices); the release returning the chord count, any key releasing it, the release velocity reaching every voice, pressure reaching every held voice, a mono allocator still routing every lane while releasing its one voice, a song lane voice untouched by both; both live entry points fanning out; and a 400-iteration bounded-extremes sweep.
- The twin laws are exact, not tolerant, and they are the core of the glide half: "the button is the mode" is eight blocks of bit-identical stereo, and the handover twin is the same set with its own mode switched off at that moment — which only works because the *histories* match.
- 58 mutants in three passes. Four first-pass survivors: two were **equivalent mutants** — a negative `n` is already caught by the unsigned range check that follows it, and the `root < 0` fast path is unreachable behaviour because the mask gates both loops — and were replaced by behaviour-changing mutants of the same shape (six lanes refused; an empty chord falling back to the played note). The other two were real gaps in the laws, both closed by fixing the test: the mask-limiting law pushed two lanes with a mask of `0x3`, so a mutant that never limited the mask was invisible (it now pushes all six bits), and the low-clamp law's chord could never reach below the keyboard, because the root lane always lands on the played key (it now uses a lane *above* the root in value, so `k` really is negative).

## Method findings (portable)

- **A momentary control cannot be stamped at fire time.** The plan said "copy into each voice as `gforce` at fire time", which makes a held-then-released button sticky: the stamp survives the release. The honest shape is a device flag plus a per-block refresh at the place that already copies device state into voices (`levi_sig_refresh`, the P9a home), and a *direct read* of the flag at the few sites that run between blocks. So the rule is: **the render reads per-block state; event-time sites read the flag.**
- **Releasing a percussive control does not finish what it started; it stops it.** With the glide law skipped entirely, a released button leaves `glt` frozen mid-slide and the voice on its new note. Both are defensible designs; the difference is a plan sentence, and the twin law caught the one that did not match the code.
- **A twin is only meaningful when the histories match.** The first handover twin compared "slid under the button, then released" against "never slid" and differed by a full cycle, not by a semitone — the oscillator phase accumulated during the gliding block is state. The fix was to build the twin out of the *same* history switched at the same moment (the panel mode off), not to loosen the law.
- **A mask is a separate contract from a count.** `levi_chord_set(s, on_flags, notes, n)` has both a bitmask and a lane count, and the law only saw the mask when the two agreed. Pushing `n` lanes with *all six bits set* is what makes "the mask is limited to `n`" observable — the same "the law must exercise the disagreement" shape as the P9c reachability probe.
- **A clamp needs a case that actually reaches it.** The root lane always lands exactly on the played key, so a chord's *lowest* note can never need the low clamp; only a lane whose note is below the root's can. The law now uses lanes `{70, 62}` played at key 4, where the second lane is genuinely negative before the clamp.
- **Ownership is worth stating as a law.** Chord release and chord pressure act on "every voice in the hold list", which is not the same as "every active voice". Asserting that a *song lane* voice survives both is what pins the boundary, and it is the only thing that can kill a mutant that drops the hold-list test.
- **Row kind is part of the text law.** The panel's `ON/OFF` branch belongs to `RI_CK_SWITCH` rows, so a SELECTOR row prints "0"/"1". Choosing SWITCH for an engine-bound on/off button (the ribbon-touch precedent, where SWITCH elsewhere means a UI page switch) gets the right text for free and states the intent; choosing SELECTOR for consistency with the sibling zone rows would have needed a text branch.
- Test/build trap: `ri_levi_matrix_route()` takes a route depth of −100..100, not the full signed byte, so a macro-precedence route written at −127 was refused and its twin law was vacuously green. Fixed by the range, not by the law.
- Mutation driver: five of the 51 first-pass kills were **build breaks** (`-Werror=unused-parameter` / `-Wunused-but-set-variable`) — a mutant that stops reading a parameter proves nothing about the laws. Every one was replaced by a mutant of the same shape that keeps the variable in use (the button *suppressing* a legato slide, "off" storing a truthy chord flag, the chord playing its own lane notes, the release reporting `n ? 1 : 0`, six lanes refused), and one replacement needed a third pass because it mixed signedness in the `?:`. All eight die behaviourally.
