## Disposition
New. Gap analysis found zero AIFF implementation anywhere (only
WBS/plan prose: "WAV/AIFF export" parity). This slice lands plain
big-endian AIFF (FORM/AIFF + COMM + SSND, 16|24-bit, 44100|48000)
in both writers with a contract pin (`t32_aiff`, audit Phase 1) +
2 goldens. AIFF-C/sowt is out (different container, stated).

## What
- `audio_io/audio.{c,h}`: `auf_aiff_header()` (54-byte builder,
  80-bit extended rate table, rc-2 on bad depth/sr) +
  `au_render_song_to_aiff()` + `AuRenderToFileAiff()` (BE
  packing through the shared s16/s24 converters); new BE byte
  writers beside the LE ones.
- `tools/render.c`: `--format wav|aiff` (default wav, else exit
  2) into process-global `g_format`; single `write_audio`
  dispatcher (all 8 call sites renamed); `write_aiff` shares the
  audio.c header/packer contract (no third implementation).
- Goldens `tests/golden/303/dc-aiff.wav` (192054 B) +
  `first-light-aiff.wav` (250340 B) + `.sha256`; audit Phase 1
  pins existence + sidecars + sha256 + determinism re-renders +
  the t32 line.
- Ledger `docs/evidence/formats/export.md`: AIFF section; status
  stays PARTIAL (AuRender/live rate + external validation open).
