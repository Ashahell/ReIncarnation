## P8e status: done (t145, 46 mutants)

- Engine: `int8_t sval[RI_LEVI_MAXSTEPS]` (64) + `sown` + `semi` inside `struct RILeviLFO` — 8 voice copies plus the shared copy, 45 tables ~2.9 KB — with per-instance cursors `RILeviSet.lsc[RI_LEVI_NLFO]` and one device-wide setter `levi_set_lfo_stepctl(set, lfo, field, val)` (0 accepted, 2 refused).
- Bit-identity: while `sown == 0` the step wave reads `lfo_step_value(n, k)` exactly as in P5a, so songs are bit-identical. The first VALUE write materialises the current ramp into all 64 entries (repeating every `n`) and sets `sown`; RAMP with a non-zero value clears `sown` on every copy (an undo, no refill); RAMP 0 leaves an owned table alone. Values are 7-bit bipolar (`sval = val - 64`, float `/63` clamped to ±1); SEMI LOCK (`RI_LEVI_LP_SEMI`, LFO param 14, `RI_LEVI_LP_N` 14 → 15) snaps a written value to a 1/12 grid (25 levels, val 70 → 69).
- Index safety: the cursor clamps to 63 on write; the read holds the index inside `n` (`if (k >= n) k = n - 1u`), so shrinking STEPS under a held index stays in range. Steps ≥ `n` are stored but never read, so the 64-entry grid can hold steps the LFO does not sound yet.
- Keys/dispatch: `RI_LEVI_LSKEY(l, f)` = `0x1300 | l << 2 | f` (LFO 1-4) and `0x1400 | f` (LFO 5); fields STEP 0 / VALUE 1 / RAMP 2, field 3 refused. Two allow-list block rules (`RI_AUTO_BLK_LEVILS0/1`) allow `0x1300-0x130E` and `0x1400-0x1402`; the other low bytes and field 3 are refused. `engine_automation` dispatches the blocks before its LEVIMOD branch (`lf` from the block, field `lo & 3`), and `app/riapp.c` mirrors both blocks into the song's UI lane.
- UI: LFO page count 2 → 3. Page 2 slot 6 is SEMI LOCK (`LFOKEY(l,14)`, FREE/LOCK) and slot 7 the STEP EDIT gate; page 3 is STEP cursor / VALUE / RAMP with slots 3-6 dead and slot 7 the gate again. New UI-only SWITCH row `RI_SLEVI_LFEDIT` 214 (`RI_SLEVI_NCTL` 215), panel slots `SLOT_LFS(f) = -(144 + f)`.
- E0 (own laws, no manual statement): the 1/12 grid; first edit materialises the ramp; the table is device-wide (all voices + shared, like `ui[]`) while phase/stagger stay per-voice; only steps `< n` sound; the panel VALUE knob mirrors the last written value (no engine→panel read path, the same standing gap as the P8c per-step display); the step table is runtime state, so song persistence rides the P10 owner review with the P8c tracks.

- Two laws were strengthened because a mutant survived honestly, and both repairs are the kind of mistake worth naming: the step-index clamp law had used three `levi_trigger` calls and then read through a helper that never advances the LFO, so `stepk` was still 0 and `k >= n` was never true; and the RAMP-0 law asserted `sown == 0` when the law is the opposite — RAMP 0 must leave an owned table owned. ## Method findings (portable)

- A mutation driver that rebuilds only the mutated module is unsound. Objects from mutant N-1 stayed in the link during mutant N, so a later "kill" could have been the previous mutant's failure and a "survival" could have been a stale object. Rebuild everything per mutant (a full `all` is cheap relative to a wrong verdict), rebuild once more at the end so the tree is consistent, and treat a run whose final test is red as a broken harness.
- `printf("... %d", setter(&A, ...), A.v[0]...)` is a lying probe: argument evaluation order is unspecified, so the read-back happens *before* the call. The "defect" it showed (a value landing one step off, then the previous write's value) was the probe, not the code. Keep the call and the read in separate statements, as the tests do.
- `ri_levi_lfo_step()` does not advance the LFO step: `lfo_advance` returns early when `oneshot == 2`. `lfo_trigger` advances `stepk` (`0xFF → 0`, else `(stepk + 1) % n`). Any law about a step index has to go through note-ons.
- Read the *order of tests* in an allow-list before concluding a key block is unavailable. The pre-code note here claimed `0x13xx` was unusable because macro routes (`RI_LEVI_MRKEY`) spill to 0x13FF; `ri_auto_allowed` tests block rules before the flat table, so a block the editor owns is judged by its own rule. The plan note was amended and the implementation kept 0x13xx for LFO 1-4.
- Lane: the guest has no `sh`, `sleep` or `export` — only the Shell-1.3 command set (`Run`, `SetEnv`, `echo`, `dir`). `--run-script` takes a *guest* path, and `spike_control.py` binds 9295 itself, so a persistent spool server must not be running at the same time. The agent dials once per boot: budget one session per VM boot and order it put → env → run → keys → log.
- Without `SetEnv RIAPP_EVLOG RAM:` the app opens a requester asking for the log name and never shows a window, while `Run >NIL:` still returns rc=0 after ~9.9 s. Two lane sessions were spent on that; the evlog file's absence plus a window list is the diagnostic, not the run's return code.
- An injected raw key auto-repeats while held: one SPACE press/release pair logged 122 play and 121 stop toggles. Harmless for a transport proof (PLAY was reached, 0 xruns), but do not count toggles as events.
- Guest-side audio is observable: the lane's `-audiodev wav` capture grows with the guest's AHI output, so peak and non-zero fraction are real numbers (peak 13354, 32.9% non-zero) rather than the "no host wav" of earlier records.
