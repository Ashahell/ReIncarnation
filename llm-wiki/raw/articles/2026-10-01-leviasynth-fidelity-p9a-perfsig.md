## Scope (P9 split)

- P9a (this slice): the performance *data*. P9b amounts (the six dim panel slots plus the stored per-op VELENV and mod-env VELCRV), P9c keyboard zones, P9d glide button + chord mode and P9e tap tempo follow. Every P9 amount/zone control needs a panel row, so P9a is device-API only — the P8d ribbon pattern — and the sources it feeds are what the amounts multiply.
- Still no live-input producer anywhere in the tree, so nothing in the tree calls the new APIs yet: `levi_note_on(set, note)` carries no velocity and is called only from tests, `app/midisend.c` is send-only. The MIDI/interop touch wiring rides the interop work. Per-zone *patches* (the real instrument's two layers) ride P10 and its chunk-ID owner review.

## P9a status: done (t146, 37 mutants)

- Engine: six set-level APIs — `levi_note_vel`, `levi_note_rel_vel`, `levi_press`, `levi_polyat`, `levi_wheel`, `levi_bend` — 0 accepted / 2 on NULL, values clamped and nothing refused beyond that. `levi_note_on`/`levi_note_off` are the velocity-127 wrappers, so songs and every existing caller are bit-identical.
- Set state: `pvel` (pending note velocity), `rvel` (pending release velocity), `press`, `wheel`, `pat[RI_LEVI_NVOICES]`, `bend` (semitones, clamped to ±24). Voice state: `nvel`/`nveloff` (raw 0..127, kept raw for the P9b amount laws) plus the normalised copies `vel01`, `veloff01`, `pat01`, `mpat01`, `wheel01`, `bsrc`, refreshed per block in `levi_voice_render_sum_stereo` — the P8d cadence, because the per-voice render has no set pointer.
- Stamps: `levi_trigger` writes `nvel`/`nveloff` from the pending note velocity and clears the reused voice's key-pressure slot; each `levi_note_off` branch re-stamps `nveloff` with the release velocity (mono voice 0, unison every voice it fired, poly the sounding voice). Mono and unison modes never release, so those voices keep the note-on velocity.
- Sources: 27 POLYAT, 28 MONOAT, 29 VELON, 30 VELOFF, 33 WHEEL, 34 BEND (`RI_LEVI_MS_N` 43) — added to the source table, the UI list and the `levi_mod_apply` source vector, so any destination can be driven by any performance signal. BEND normalises against the P6b bend range (`bsrc = clamp(bend / vbendrng, ±1)`), whose UI maps 0..127 to 0..24 semitones with a default of 2: range 0 reads 0 (fail closed) and ±range reads full scale.
- Pitch: `bsrc * vbendrng` joins the P6b per-sample `vsemi` offset that detune, vibrato, glide and analog feel already feed. The first sketch had a flagged per-block frequency retune; the offset is the law the engine already has, costs one add, and composes instead of fighting a glide in flight — the plan bullet was amended at code time rather than the code changed to match the sketch.
- E0 (own laws, no manual statement): no route means no sound change; live default velocity 127; release velocity starts as the note velocity; per-key pressure is dropped when a voice is reused for another key; aftertouch and wheel are absolute levels (the caller returns them to 0, no spring return invented); poly aftertouch is per key while channel pressure reaches every voice; a signal set mid-block is heard from the next block; song lanes (`levi_trigger`/`levi_release`, lane==voice) keep 127/127.
- Proof: audit 0/0 PASS; ASan/UBSan clean on t146 plus t140/t142/t143/t144/t145; mutation 37/37 killed. On-target: the audit's AROS RIAPP link gate passes (0 unresolved, 0 r12 base moves) and the guest binary carries all six new entry points (`x86_64-aros-nm`: `levi_note_vel`, `levi_note_rel_vel`, `levi_press`, `levi_polyat`, `levi_wheel`, `levi_bend`). **Lane run deferred** — the single spool session is held by another lane (`spike_server.py serve --port 9091` since 16:06 with the `nvkb1` guest connected) and a guest dials in once per boot, so the riaudio boot could not be driven; the VM is left booted and the run proof moves to the P9b pass. Standing gaps unchanged (panel pixels, encoder-press nav).

## Tests

- t146 (`tests/unit/t146_levi_perfsig.c`, 16 law groups): API contracts and NULL refusals; the clamps (velocity 200 → 127, release 200 → 127, pressure 200 → 127, wheel 200 → 127, bend ±40 → ±24); note velocity stamped at fire and kept across a release, with a velocity-less note-on reusing the last note velocity; the release stamp in all three release branches (mono, unison every voice, poly); the per-voice key-pressure clear on voice reuse; poly aftertouch per key (one block of latency, the other voice untouched) and channel pressure reaching every voice; the six normalised copies and each one's one-block latency; bend against the range (default 2 semitones, ±range reads ±1, past the range clamps at ±1, range 0 reads 0, range 24 reads `bend/24`); the pitch law measured against a semitone-equal key up (7 semitones of bend over the 24 semitone range lands within 1e-3 of note 67, float-tolerant because the pitch is a table lookup times a power, not one rounding); six source laws as same-age twin sets routed to the VCA level at depth 100, read as **peak** rather than samples so a bend pitch move cannot pass for a source move; the no-route bit-identity law; source ids, names and UI indices.
- 37 mutants, all killed: the six API bodies (velocity/release/pressure/wheel/bend stamps, per-key pressure routed to the wrong voice, the release-velocity stamp in each of the three branches, the release path writing the note velocity, the bend setter never moving the value); all seven init defaults; all six per-block refresh lines (constant, silent, pressure read from voice 0 for all); the bend normalisation (fixed 2 semitones, unnormalised, both clamps widened) and the pitch law (inverted, range dropped); all six `src[...]` lines (silent, and VELOFF reading the note velocity).
- Three laws were strengthened because a mutant survived honestly, and each repair is a mistake worth naming. The audible twins were first routed to the D.FILTER cutoff, which a voice barely moves in the default patch — the pair passed on a 0.8 % sample difference, a law thin enough to pass for the wrong reason — so the destination became the VCA level (`*evlevel *= 1 + x`) and the comparison became peak amplitude. The bend clamp laws first bent 7 semitones over the default 2 semitone range, i.e. 3.5 before the clamp, so *widening* the clamp to ±2 still clamped to ±1 and both clamp mutants survived; they now bend 3 semitones (1.5 before the clamp). The BEND source law first compared samples, which differ anyway because the same signal also moves the pitch, so the source mutant survived; it now reads the level like every other source law. A fourth law (the pending note velocity surviving a release) was added because a stray `pvel` write in the release path was invisible until the next velocity-less note-on.

## Method findings (portable)

- An audible-law destination is a choice, and the "obvious" one can be silent in practice. On the VCA level destination a depth-100 route scales the amp by `1 + x` (source 1.0 → ×1.57), while the D.FILTER cutoff destination is barely audible in the default patch even though the route is registered and the source reaches `ecut`. A twin law that passed on a 0.8 % difference was a false comfort.
- When a source feeds both a matrix route and a direct path, the twin *samples* always differ and the test proves nothing about the source. Read a quantity only the route can move (level, not pitch) and the mutant dies.
- A clamp law must place its test value *between* the good clamp and a plausible wrong one. The bent value 7 semitones over a 2 semitone range (3.5 before the clamp) is still below a widened ±2 threshold, so a mutant that widened the threshold to ±2 and clamped to ±1 produced identical behaviour.
- `levi_set_param_ui(set, dev, RI_CTL_LEVI_VBENDRNG, 2)` sets 0.378 semitones, not 2. The P6b UI maps 0..127 to 0..24 semitones and the default is already 2.0, so "set the range to 2" is a no-op that looks like a working test setup, and it hid two clamp mutants.
- Test traps: a note-off with no render in between is instant (the envelope never left stage D, so the release tail carried no signal and a VELOFF twin pair came out bit-identical); a matrix source of 0 on a depth-100 route silences the voice, so twins keep their source off the closing stop; `RI_LEVI_DM_VCA` param 0 is LEVEL, the one destination a source is guaranteed to move audibly.
- Host tooling does not belong in `/tmp`. The scratch dir was wiped twice by host restarts mid-slice (killing `mut.sh`, `asan.sh` and the todo list, and leaving a mutation applied in `engine/dsp/levi.c` when a run was interrupted). Driver scripts now live in `/home/miller/Work/vms/ri-p9/`. Two lessons ride along: always `git diff` the mutated file after an interrupted run before trusting the tree, and back the file up to a durable path, not `/tmp`.
- Python buffers stdout when redirected, so a backgrounded mutation run writes an empty log until it exits. Read the log after completion, not during.
- The lane spool is a single anonymous session. `spike_control.py` binds the port itself, so a second lane cannot even start while `spike_server.py serve` holds it, and a job submitted to that spool is executed by whichever guest holds the slot — which may be another session's lane. One lane at a time is a hard rule, and "the other lane is busy" is a legitimate reason to defer a run proof and say so.
